# E-commerce Product Analytics

Комплексный аналитический проект на данных бразильского маркетплейса Olist. Проект охватывает проверку качества данных, расчёт бизнес-метрик, когортный анализ, RFM-сегментацию, статистическую проверку гипотез, SQL-анализ и создание интерактивных дашбордов.

## Цель проекта

Исследовать поведение покупателей и работу доставки, определить ключевые бизнес-показатели и подготовить рекомендации для повышения повторных покупок и клиентской удовлетворённости.

Основные вопросы исследования:

- Как менялись количество заказов и стоимость проданных товаров?
- Какова доля клиентов, совершающих повторные покупки?
- Какие клиентские сегменты являются наиболее многочисленными и ценными?
- Как сроки и задержки доставки связаны с оценками покупателей?
- Какие показатели следует контролировать бизнесу?

## Этапы анализа

### 1. Проверка качества данных

- Загружены и изучены девять связанных таблиц.
- Проверены размеры таблиц, типы данных, ключи, пропуски и дубликаты.
- Даты преобразованы в формат `datetime`.
- Проверена логическая последовательность событий заказа.
- Установлено, что таблицы товаров, платежей и отзывов содержат несколько строк на один заказ.

### 2. Подготовка аналитической таблицы и бизнес-метрик

Таблицы товаров, платежей и отзывов предварительно агрегированы до уровня заказа. После объединения сформирован аналитический датасет, содержащий одну строку на один заказ.

Рассчитаны:

- количество заказов;
- количество покупателей;
- стоимость проданных товаров;
- средний чек;
- количество товаров в заказе;
- продолжительность доставки;
- доля задержанных заказов;
- средняя оценка;
- доля отменённых заказов;
- месячная динамика показателей.

Первый и последний месяцы содержат неполные данные и не используются для прямого сравнения с полными календарными месяцами.

### 3. Когортный анализ

Клиенты распределены по месяцу первой доставленной покупки. Для каждой когорты рассчитана доля клиентов, вернувшихся через определённое количество месяцев.

Основные результаты:

- около 3% клиентов совершили более одной покупки;
- средний retention через один месяц составил около 0,48%;
- через три месяца — около 0,25%;
- через шесть месяцев — около 0,26%;
- большинство клиентов не возвращается за повторной покупкой в течение доступного периода наблюдения.

Последние когорты имеют более короткое окно наблюдения, поэтому отсутствующие будущие месяцы не интерпретируются как нулевой retention.

### 4. RFM-сегментация

Для каждого клиента рассчитаны:

- `Recency` — количество дней с последней покупки;
- `Frequency` — количество завершённых заказов;
- `Monetary` — общая стоимость приобретённых товаров.

Клиенты распределены по сегментам:

- Champions;
- Loyal customers;
- New customers;
- At risk;
- High-value one-time;
- Regular one-time;
- Inactive one-time.

Основные наблюдения:

- крупнейшую группу составляют клиенты с одной покупкой;
- сегмент `High-value one-time` сформировал наибольший денежный объём;
- сегмент `At risk` содержит ранее ценных или повторных покупателей, которых можно попытаться вернуть;
- для новых клиентов целесообразно стимулировать вторую покупку;
- для постоянных клиентов можно развивать программу лояльности и персональные рекомендации.

### 5. Статистический анализ доставки и оценок

Для анализа использованы доставленные заказы с известными сроками доставки и отзывами.

Основные результаты:

- средняя оценка своевременных заказов — 4,294;
- средняя оценка задержанных заказов — 2,567;
- доля оценок 1–2 среди своевременных доставок — 9,2%;
- доля оценок 1–2 среди задержанных доставок — 54,0%;
- критерий хи-квадрат показал статистически значимую связь между задержкой и низкой оценкой;
- Cramér’s V составил 0,364, что соответствует среднему размеру эффекта.

Средняя оценка уменьшается с увеличением срока доставки:

| Срок доставки | Количество заказов | Средняя оценка | Доля оценок 1–2 |
|---|---:|---:|---:|
| 0–7 дней | 25 933 | 4,418 | 7,4% |
| 8–14 дней | 39 997 | 4,312 | 8,9% |
| 15–21 день | 17 582 | 4,140 | 11,6% |
| 22–30 дней | 7 882 | 3,607 | 24,3% |
| 31+ день | 4 430 | 2,254 | 62,9% |

Обнаруженная связь не доказывает причинное влияние. На оценки также могут влиять качество товара, цена, продавец и другие факторы.

### 6. SQL-анализ

Расчёты дополнительно реализованы в DuckDB SQL.

SQL-часть включает:

- загрузку исходных CSV;
- предварительную агрегацию таблиц до уровня заказа;
- построение объединённой аналитической таблицы;
- расчёт KPI и месячных метрик;
- анализ доставки;
- расчёт повторных покупок;
- когортный анализ;
- RFM-сегментацию;
- экспорт агрегированных таблиц для DataLens.

### 7. Визуализация

В Yandex DataLens созданы три интерактивных дашборда:

1. обзор бизнеса;
2. клиенты, RFM-сегментация и retention;
3. доставка и оценки покупателей.

## Бизнес-рекомендации

1. Стимулировать вторую покупку новых клиентов с помощью персональных предложений после первого заказа.
2. Развивать программу лояльности для повторных и ценных покупателей.
3. Проводить реактивационные кампании для сегмента `At risk`.
4. Отдельно контролировать долю доставок длительностью более 21 дня.
5. Анализировать регионы, продавцов и товарные категории с наиболее высокой долей задержек.
6. Отслеживать долю оценок 1–2 совместно с показателями доставки.
7. Проверять эффективность предложенных действий с помощью A/B-тестов.

## Как запустить проект

### 1. Клонировать репозиторий

```bash
git clone https://github.com/Iluxa-58/ecommerce_product_analysis.git
cd ecommerce_product_analytics
```

### 2. Создать виртуальное окружение

```bash
python -m venv .venv
source .venv/bin/activate
```

Для Windows:

```bash
.venv\Scripts\activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Скачать данные

Скачайте [Olist Brazilian E-Commerce Dataset](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce) и поместите исходные CSV-файлы в:

```text
data/raw/
```

### 5. Запустить Jupyter

```bash
jupyter notebook
```

Ноутбуки рекомендуется запускать последовательно:

```text
01_data_quality.ipynb
02_business_metrics.ipynb
03_cohort_retention.ipynb
04_customer_segmentation.ipynb
05_statistical_analysis.ipynb
```

SQL-файлы также выполняются по порядку:

```text
01_create_tables.sql
02_business_metrics.sql
03_customer_analysis.sql
```

## Ограничения исследования

- Данные охватывают ограниченный исторический период.
- Последние когорты имеют более короткое окно наблюдения.
- Датасет не содержит полной информации о маркетинговых каналах и поведении пользователей до покупки.
- Статистическая связь между доставкой и оценками не доказывает причинность.
- Предложенные бизнес-действия требуют проверки с помощью контролируемых экспериментов.
